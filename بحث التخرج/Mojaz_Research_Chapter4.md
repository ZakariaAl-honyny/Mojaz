# الفصل الرابع: تصميم النظام والواجهات (System Design & Interfaces)

## 4.1 مقدمة (Introduction)
تنتقل هذه المرحلة من "ماذا يفعل النظام" إلى "كيف سيتم بناء النظام". يركز التصميم على المعمارية البرمجية والهوية البصرية التي تضمن أعلى مستويات القبول لدى المستخدمين. تم استلهام التصميم من واجهات "أبشر" السعودية لتحقيق الألفة البصرية والاحترافية الحكومية.

## 4.2 المعمارية البرمجية (System Architecture)

### 4.2.1 المعمارية النظيفة (Clean Architecture)
تم تقسيم النظام إلى مشروع متعدد الطبقات لضمان سهولة الاختبار والصيانة:
1.  **Domain Project**: يحتوي على الكيانات (Entities) مثل `Applicant`, `Manager`, `Application`. لا يعتمد على أي مكتبات خارجية.
2.  **Application Project**: يضم منطق الأعمال (Business Logic) والخدمات (Services). يتم فيه التحقق من القواعد (مثلاً: لا يمكن تجديد رخصة لم تنتهِ بعد).
3.  **Infrastructure Project**: يحتوي على تفاصيل التنفيذ (Implementation details) مثل الاتصال بـ SQL Server، أو استدعاء APIs لخدمات الرسائل (Twilio).
4.  **Web API Project**: طبقة العرض والتحكم (Controllers Mapping).

### 4.2.2 واجهات البرمجة (RESTful APIs)
تم بناء أكثر من 50 نقطة نهاية (Endpoint) تتبع المعايير العالمية، حيث ترجع كل استجابة بنموذج موحد:
```json
{
  "success": true,
  "data": { ... },
  "message": "تمت العملية بنجاح",
  "errors": null,
  "statusCode": 200
}
```

## 4.3 التصميم المرئي (UI Design)

### 4.3.1 نظام الألوان (Color Palette)
-   **King Blue (#1a3a8f)**: اللون الأساسي، يعبر عن الثقة والصفة الرسمية.
-   **Government Gold (#D4A017)**: اللون الثانوي للتفاعل والتميز.
-   **الخلفية البيضاء الصافية**: لتقليل التشتت البصري وتحسين القراءة.

### 4.3.2 الهوية والخطوط
تم استخدام خط **IBM Plex Sans Arabic** كخط افتراضي لضمان وضوح النصوص في مختلف أحجام الشاشات، مع الالتزام التام باتجاه القراءة من اليمين إلى اليسار (RTL).

## 4.4 واجهات المتقدم (Applicant Interfaces)
1.  **صفحة الترحيب (Landing Page)**: تهدف لجذب المستخدمين وتعريفهم بالخدمات المتاحة.
2.  **بوابة تسجيل الدخول الذكية**: تطلب رقم الهوية وإدخال رمز التحقق OTP الذي يصل لهاتف المتقدم.
3.  **لوحة تتبع الطلبات (Live Tracking)**: تعرض للمتقدم شريط تقدم (Progress Bar) يوضح في أي مرحلة من الـ 10 مراحل يقع طلبه حالياً.
4.  **نموذج الطلب (Wizard Form)**: نموذج مجزء لعدة خطوات لتسهيل عملية إدخال البيانات دون ملل.

## 4.5 واجهات الموظفين (Employee Dashboards)
1.  **واجهة الاستقبال**: تتيح البحث السريع عن الطلبات عبر رقم الهوية ومراجعة المرفقات بضغطة زر.
2.  **واجهة الطبيب**: مصممة بشكل بسيط يدعم الإدخال السريع للبيانات الحيوية.
3.  **لوحة تحكم المدير**: تحتوي على رسوم بيانية (Charts) توضح توازن العمل بين الفاحصين واكتشاف مناطق التأخير وبطء الانتقال بين المراحل.

## 4.6 التصميم المستجيب (Responsive Design)
بُنيت جميع الواجهات باستخدام **Tailwind CSS 4** لضمان عملها بمرونة كاملة على متصفحات الهواتف الذكية (Mobile-First Approach)، حيث أن أغلب المواطنين يفضلون إنجاز معاملاتهم عبر الجوال.
