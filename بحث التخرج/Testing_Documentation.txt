# وثيقة الاختبارات منصة مُجاز لإصدار رخص القيادة

## المقدمة

تُعدّ الاختبارات جزءاً أساسياً من أي مشروع برمجي متكامل، وخاصة الأنظمة الحكومية التي تتطلب أعلى مستويات الجودة والموثوقية. تهدف هذه الوثيقة إلى توثيق استراتيجية الاختبارات المتبعة في منصة مُجاز لإصدار رخص القيادة، والتي تشمل اختبارات الوحدة والاختبارات التكاملية واختبارات التدقق من طرف إلى طرف. يعتمد فريق التطوير على إطار عمل xUnit لكتابة اختبارات الوحدة، مع استخدام مكتبة Moq لنمذجة التبعيات ومكتبة FluentAssertions للتحقق من النتائج المتوقعة.

تتبع المنصة منهجية التطوير المدفوعة بالاختبارات (Test-Driven Development) لضمان أن كل ميزة جديدة تُكتَب بناءً على اختبارات محددة مسبقاً. هذا النهج يضمن تغطية شاملة لأغلب السيناريوهات المحتملة، بما فيها الحالات الحدية وحالات الخطأ، مما يُحسّن جودة الكود ويقلل من عدد الأخطاء في بيئة الإنتاج.

---

## القسم الأول: اختبارات الوحدة

### ١.١ الإطار العام لاختبارات الوحدة

تستخدم منصة مُجاز إطار عمل xUnit.NET لكتابة اختبارات الوحدة، ويُعتبر هذا الإطار من أكثر أطر الاختبار شعبية في بيئة .NET نظراً لبساطته ومرونته. تُنظَّم اختبارات الوحدة في مجلد منفصل ضمن الحل البرمجي، حيث يوجد مشروع اختبارات خاص بكل طبقة من طبقات التصميم المعماري. على سبيل المثال، تُوجد مشاريع مثل Mojaz.Application.Tests للاختبارات الخاصة بطبقة التطبيق، وMojaz.Domain.Tests لاختبارات طبقة النطاق.

يهدف فريق التطوير إلى تحقيق تغطية كود لا تقل عن 80% لجميع طبقات العمل الرئيسي، مع التركيز بشكل خاص على طبقة النطاق (Domain) وطبقة التطبيق (Application) اللتين تحتويان على معظم المنطق التجاري. تُقاس التغطية باستخدام أداة Coverlet التي تُدمج مع خط أنابيب CI/CD لتوليد تقارير التغطية تلقائياً.

### ١.٢ هيكل ملف الاختبار

يتبع كل ملف اختبارات هيكلاً موحداً يسهل قراءته وصيانته. يبدأ اسم الملف دائماً باسم الكلاسة المُختبرة متبوعاً بعبارة "Tests" أو "Tests.cs" للدلالة على أنه ملف اختبارات. داخل كل ملف، تُنظَّم حالات الاختبار باستخدام سمة Fact لمن标记 methods التي لا تأخذ معاملات، وسمة Theory للاختبارات التي تحتاج معاملات متعددة.

فيما يلي مثال توضيحي لاختبار وحدة بسيط:

```csharp
using Xunit;
using Moq;
using FluentAssertions;
using Mojaz.Application.Services;
using Mojaz.Domain.Entities;
using Mojaz.Domain.Interfaces;
using System.Threading.Tasks;
using System;

namespace Mojaz.Application.Tests.Services
{
    public class ApplicationWorkflowServiceTests
    {
        private readonly Mock<IApplicationRepository> _mockApplicationRepo;
        private readonly Mock<IUnitOfWork> _mockUnitOfWork;
        private readonly Mock<IWorkflowEngine> _mockWorkflowEngine;
        private readonly ApplicationWorkflowService _service;

        public ApplicationWorkflowServiceTests()
        {
            _mockApplicationRepo = new Mock<IApplicationRepository>();
            _mockUnitOfWork = new Mock<IUnitOfWork>();
            _mockWorkflowEngine = new Mock<IWorkflowEngine>();
            _service = new ApplicationWorkflowService(
                _mockApplicationRepo.Object,
                _mockUnitOfWork.Object,
                _mockWorkflowEngine.Object);
        }

        [Fact]
        public async Task SubmitApplication_ValidRequest_ShouldReturnSuccess()
        {
            // Arrange
            var request = new CreateApplicationRequest
            {
                ApplicantId = Guid.NewGuid(),
                LicenseCategoryId = Guid.NewGuid(),
                ServiceType = ServiceType.NewLicense
            };

            _mockApplicationRepo
                .Setup(x => x.AddAsync(It.IsAny<Application>()))
                .Returns(Task.CompletedTask);

            _mockUnitOfWork
                .Setup(x => x.SaveChangesAsync(default))
                .ReturnsAsync(1);

            // Act
            var result = await _service.SubmitApplicationAsync(request);

            // Assert
            result.Success.Should().BeTrue();
            result.Message.Should().Be("تم تقديم الطلب بنجاح");
        }
    }
}
```

### ١.٣ اختبار الخدمات الأساسية

تُعدّ خدمات طبقة التطبيق من أهم المكونات التي تحتاج إلى اختبارات وحدة مكثفة، لأنها تحتوي على المنطق التجاري الرئيسي للنظام. تشمل هذه الخدمات خدمات معالجة الطلبات، وخدمات سير العمل، وخدمات المدفوعات، وخدمات الإشعارات، وخدمات التحقق من الهوية. في هذا القسم، نستعرض أمثلة عملية لاختبارات بعض هذه الخدمات.

#### ١.٣.١ اختبار خدمة سير العمل

خدمة ApplicationWorkflowService هي المسؤولة عن إدارة دورة حياة طلب ترخيص القيادة. تتعامل هذه الخدمة مع انتقالات الحالة المختلفة مثل تقديم الطلب، ومراجعة الطلب، والموافقة أو الرفض، وجدولة المواعيد، وإصدار الرخصة. يتطلب اختبار هذه الخدمة محاكاة مستودعات البيانات ومحرك سير العمل لعزل الكود المُختبَر عن التبعيات الخارجية.

```csharp
[Fact]
public async Task TransitionStatus_ValidTransition_ShouldUpdateStatus()
{
    // Arrange
    var applicationId = Guid.NewGuid();
    var application = new Application
    {
        Id = applicationId,
        Status = ApplicationStatus.Submitted,
        ApplicationNumber = "MOJ-2025-12345678"
    };

    _mockApplicationRepo
        .Setup(x => x.GetByIdAsync(applicationId))
        .ReturnsAsync(application);

        .Setup(x => x.CanTransition(
            ApplicationStatus.Submitted,

        .Returns(true);

        .Setup(x => x.UpdateAsync(It.IsAny<Application>()))
        .Returns(Task.CompletedTask);

        .Setup(x => x.SaveChangesAsync(default))
        .ReturnsAsync(1);

        applicationId,
        ApplicationStatus.InReview,
        "مراجعة الطلب");

    // Assert
    result.Success.Should().BeTrue();
    application.Status.Should().Be(ApplicationStatus.InReview);
    _mockApplicationRepo.Verify(x => x.UpdateAsync(It.IsAny<Application>()), Times.Once);
```

#### ١.٣.٢ اختبار خدمة التحقق من الأعمار

من أهم القواعد التجارية في نظام مُجاز هي التحقق من_age المتقدم للتقدم لكل فئة رخصة. تختلف السن الأدنى لكل فئة، فمثلاً فئة الرخصة A تتطلب age 16 سنة، وفئة B تتطلب 18 سنة، بينما تتطلب الفئات C وD وE age 21 سنة. تُنفَّذ هذه القاعدة في خدمة AgeVerificationService التي يجب اختبارها بشكل دقيق.

```csharp
public class AgeVerificationServiceTests
{
    private readonly Mock<ISystemSettingsService> _mockSettings;
    private readonly AgeVerificationService _service;

    public AgeVerificationServiceTests()
    {
        _mockSettings = new Mock<ISystemSettingsService>();
        _service = new AgeVerificationService(_mockSettings.Object);
    }

    [Theory]
    [InlineData(LicenseCategory.A, 16, true)]
    [InlineData(LicenseCategory.A, 15, false)]
    [InlineData(LicenseCategory.B, 18, true)]
    [InlineData(LicenseCategory.B, 17, false)]
    [InlineData(LicenseCategory.C, 21, true)]
    [InlineData(CategoryCategory.C, 20, false)]
    [InlineData(LicenseCategory.D, 21, true)]
    [InlineData(LicenseCategory.D, 19, false)]
    public async Task VerifyAge_MultipleCategories_ShouldReturnCorrectResult(
        LicenseCategory category,
        int age,
        bool expectedResult)
    {
        // Arrange
        var requiredAge = category switch
        {
            LicenseCategory.A => 16,
            LicenseCategory.B => 18,
            LicenseCategory.C => 21,
            LicenseCategory.D => 21,
            LicenseCategory.E => 21,
            LicenseCategory.F => 18,
            _ => 18
        };

        _mockSettings
            .Setup(x => x.GetSettingValueAsync($"MIN_AGE_CATEGORY_{category}"))
            .ReturnsAsync(requiredAge.ToString());

        var request = new AgeVerificationRequest
        {
            Category = category,
            DateOfBirth = DateTime.UtcNow.AddYears(-age)
        };

        // Act
        var result = await _service.VerifyAgeAsync(request);

        // Assert
        result.IsValid.Should().Be(expectedResult);
        if (!expectedResult)
        {
            result.ErrorMessage.Should().Contain("السن أقل من");
        }
    }
}
```

### ١.٤ اختبار المدققات

تُستخدم مكتبة FluentValidation لكتابة قواعد التحقق من صحة البيانات الواردة من العملاء. تتطلب المدققات (Validators) اختبارات مكثفة للتأكد من أنها تكتشف جميع الأخطاء المحتملة وتقبل البيانات الصحيحة. يُعدّ اختبار المدققات أمراً بسيطاً لأن إطار FluentValidation يوفر طريقة سهلة لاختبار القواعد.

### ١.٥ اختبار حالات الخطأ والحالات الحدية

الأخطاء والحالات الحدية هي التي تكشف عن绝大部分 المشاكل في الأنظمة البرمجية. لذلك، فإن الاختبارات الجيدة يجب أن تغطي هذه الحالات بشكل مكثف. في نظام مُجاز، هناك عدة حالات خطأ يجب اختبارها، مثل طلب غير موجود، وحالة تطبي�� غير صالحة للتحويل، ومحاولة تقديم طلبين نشطين في نفس الوقت، وانتهاء صلاحية رمز OTP، وفشل عملية الدفع.

```csharp
[Fact]
public async Task SubmitApplication_ExistingActiveApplication_ShouldReturnConflict()
{
    // Arrange
    var applicantId = Guid.NewGuid();
    var existingApplication = new Application
    {
        Id = Guid.NewGuid(),
        ApplicantId = applicantId,
        Status = ApplicationStatus.InReview,
        ApplicationNumber = "MOJ-2025-11111111"
    };

    _mockApplicationRepo
        .Setup(x => x.GetActiveApplicationByApplicantAsync(applicantId))
        .ReturnsAsync(existingApplication);

    var request = new CreateApplicationRequest
    {
        ApplicantId = applicantId,
        LicenseCategoryId = Guid.NewGuid(),
        ServiceType = ServiceType.NewLicense
    };

    // Act
    var result = await _service.SubmitApplicationAsync(request);

    // Assert
    result.Success.Should().BeFalse();
    result.StatusCode.Should().Be(409);  // Conflict
    result.Errors.Should().Contain("يوجد طلب نشط");
}

[Fact]
public async Task SubmitApplication_DatabaseFailure_ShouldThrowException()
{
    // Arrange
    _mockApplicationRepo
        .Setup(x => x.AddAsync(It.IsAny<Application>()))
        .ThrowsAsync(new DbUpdateException("Database connection failed"));

    var request = new CreateApplicationRequest
    {
        ApplicantId = Guid.NewGuid(),
        LicenseCategoryId = Guid.NewGuid(),
        ServiceType = ServiceType.NewLicense
    };

    // Act & Assert
    await Assert.ThrowsAsync<DbUpdateException>(
        () => _service.SubmitApplicationAsync(request));
}
```

## القسم الثاني: الاختبارات التكاملية

### ٢.١ الإعداد باستخدام WebApplicationFactory

توفر مكتبة Microsoft.AspNetCore.Mvc.Testing فئة WebApplicationFactory التي تسمح بتشغيل تطبيق ASP.NET Core الكامل في بيئة الاختبار. يُتيح ذلك اختبار نقاط النهاية API Together مع قاعدة البيانات الفعلية أو قاعدة بيانات محاكاة، مما يضمن أن جميع المكونات تعمل معاً بشكل صحيح. في منصة مُجاز، نستخدم هذه المكتبة untuk menguji المتحكمات (Controllers) ونقاط النهاية المختلفة.

يُنشأ ملف Program.cs للاختبارات يتضمن تكوين التطبيق الكامل، بما في ذلك خدمات قاعدة البيانات والتبعيات الأخرى. يمكن استخدام قاعدة بيانات SQLite في بيئة الاختبار لتسريع العمليات وتجنب التلوث ببيانات الإنتاج.

```csharp
using Microsoft.AspNetCore.Mvc.Testing;
using Microsoft.EntityFrameworkCore;
using Microsoft.Extensions.DependencyInjection;
using Mojaz.Infrastructure.Data;
using Mojaz.API;
using System;

namespace Mojaz.API.Tests.Integration
{
    public class MojazWebApplicationFactory : WebApplicationFactory<Program>
    {
        protected override void ConfigureWebHost(IWebHostBuilder builder)
        {
            builder.UseEnvironment("Testing");

            builder.ConfigureServices(services =>
            {
                // Remove the real database context
                var descriptor = services.SingleOrDefault(
                    d => d.ServiceType == typeof(DbContextOptions<MojazDbContext>));
                if (descriptor != null)
                {
                    services.Remove(descriptor);
                }

                // Add testing database
                services.AddDbContext<MojazDbContext>(options =>
                    options.UseInMemoryDatabase("TestingDb_" + Guid.NewGuid()));

                // Build the service provider
                var sp = services.BuildServiceProvider();

                // Create and seed the database
                using (var scope = sp.CreateScope())
                {
                    var db = scope.ServiceProvider.GetRequiredService<MojazDbContext>();
                    db.Database.EnsureCreated();
                    SeedTestData(db);
                }
            });
        }

        private void SeedTestData(MojazDbContext db)
        {
            // Add test users
            db.Users.Add(new Domain.Entities.User
            {
                Id = Guid.Parse("11111111-1111-1111-1111-111111111111"),
                Email = "test@example.com",
                FullName = "مستخدم تجريبي",
                Role = Domain.Enums.UserRole.Applicant
            });
            db.SaveChanges();
        }
    }
}
```

### ٢.٢ اختبار نقاط النهاية API

تُختبر نقاط النهاية API باستخدام عميل HTTP مباشر يتم إنشاؤه من Factory. يمكن إرسال طلبات HTTP حقيقية والتحقق من الاستجابات، وهذا يشمل التحقق من حالة الاستجابة (Status Code) وهيكل جسم الاستجابة (Response Body).

```csharp
public class ApplicationsControllerIntegrationTests : IClassFixture<MojazWebApplicationFactory>
{
    private readonly MojazWebApplicationFactory _factory;
    private readonly HttpClient _client;

    public ApplicationsControllerIntegrationTests(MojazWebApplicationFactory factory)
    {
        _factory = factory;
        _client = factory.CreateClient();
    }

    [Fact]
    public async Task GetApplications_AuthenticatedUser_ShouldReturnApplications()
    {
        // Arrange
        var token = await GetAuthTokenAsync();
        _client.DefaultRequestHeaders.Authorization = 
            new AuthenticationHeaderValue("Bearer", token);

        // Act
        var response = await _client.GetAsync("/api/v1/applications");

        // Assert
        response.StatusCode.Should().Be(HttpStatusCode.OK);
        
        var content = await response.Content.ReadAsStringAsync();
        var result = JsonSerializer.Deserialize<ApiResponse<PagedResult<ApplicationDto>>>(

        {
            licenseCategoryId = Guid.NewGuid(),
            serviceType = "NewLicense",

            fullName = "أحمد محمد",

            Encoding.UTF8,

        // Act
        var response = await _client.PostAsync("/api/v1/applications", jsonContent);

        // Assert
        response.StatusCode.Should().Be(HttpStatusCode.Unauthorized);

            JsonSerializer.Serialize(request),
```

### ٢.٣ اختبار تدفق المصادقة

 تدفق المصادقة هو من أهم العمليات في أي تطبيق، ويتضمن تسجيل الدخول وتسجيل الخروج والتحقق من الرمزOTP وإنشاء رمز JWT. في منصة مُجاز، يتم اختبار هذا التدفق بالكامل للتأكد من أن نظام المصادقة يعمل بشكل صحيح وآمن.

```csharp
public class AuthenticationFlowIntegrationTests : IClassFixture<MojazWebApplicationFactory>
```

### ٤.٥ اختبار إصدار الرخصة

 اختبار إصدار الرخصة هو من أهم الاختبارات，因为它 يضمن أن الرخصة تُنشأ بشكل صحيح بعد استيفاء جميع المتطلبات. يجب التحقق من أن رقم الرخصة فريد، وأن تاريخ الانتهاء صحيح وفقاً لفئة الرخصة، وأن جميع البيانات الشخصية صحيحة.

تُشكّل استراتيجية الاختبارات الشاملة التي اتبعها فريق تطوير منصة مُجاز أساساً متيناً لضمان جودة وموثوقية النظام. بدءاً من اختبارات الوحدة التي تتحقق من صحة كل وحدة برمجية بشكل منفصل، مروراً بالاختبارات التكاملية التي تضمن عمل المكونات معاً بشكل صحيح، وصولاً إلى اختبارات E2E التي تحاكي تجربة المستخدم الحقيقية، غطينا جميع المستويات الممكنة من الاختبارات.

إن目标的تحقيق تغطية كود تفوق 79% يُثبت التزام الفريق بتقديم منتج عالي الجودة يلبّي احتياجات المستخدمين ويتوافق مع أعلى المعايير الحكومية. ستستمر عملية تحسين الاختبارات وإضافة حالات جديدة مع تطور المنصة وإضافة ميزات جديدة، مما يضمن استمرارية الجودة على المدى الطويل.
