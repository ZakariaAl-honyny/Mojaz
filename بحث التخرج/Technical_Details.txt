================================================================================
                   الفصل الرابع: التصميم التفصيلي للنظام
================================================================================

يُعرض هذا الفصل البنية التقنية الكاملة لنظام مُجاز، بدءاً من التقنيات المُستخدمة وصولاً إلى تصميم قاعدة البيانات ومنظومة العمل.

--------------------------------------------------------------------------------

4.1_stack_tech ================================================================================
                              4.1 المكدس التقني (Tech Stack)
--------------------------------------------------------------------------------

يُمثّل نظام مُجاز حلاً متكاملاً يعتمد على مجموعة من التقنيات الحديثة والمتطورة لتوفير أداء عالٍ وقابلية للتوسع. فيما يلي التفصيل الكامل لكل مكوّن:

------------------------------------------------------------------------------

4.1.1 _backend ------------------------------------------------------------------------------

يُستخدم ASP.NET Core 8 كإطار عمل رئيسي للواجهة البرمجية الخلفية (Backend Framework). يُعد هذا الإصدار أحدث إصدار مستقر من منصة .NET، ويتميز بمزايا متعددة تشمل:

- أداء عالٍ جداً يعتمد على Kestrel Web Server المُحسّن
- دعم متقدم للبرمجة غير المتزامنة (Async/Await)
- نظام حقن التبعيات (Dependency Injection) المدمج
- دعم لـ gRPC للتواصل بين الخدمات
- تحسينات أمنية مدمجة للحماية من الهجمات الشائعة

يُستخدم Entity Framework Core 8 كمُنظم كائنات قواعد البيانات (Object-Relational Mapper - ORM). يوفر هذا الإطار:

- قدرة عالية على التعامل مع قواعد البيانات بطريقة موجهة للكائنات
- دعم كامل لـ Language Integrated Query (LINQ)
- إدارة آلية لتهجير قاعدة البيانات (Database Migrations)
- دعم مؤقت للذاكرة (In-Memory Provider) لأغراض الاختبار
- تحسين الاستعلامات من خلال تجميع الاستعلامات (Query Caching)

يُستخدم SQL Server 2022 كقاعدة بيانات علائقية (Relational Database). تشمل مزايا هذا الاختيار:

- دعم معاملات موزعة (Distributed Transactions)
- أمان متقدم على مستوى الأعمدة (Column-Level Security)
- دعم للبيانات المؤقتة (Temporal Tables)
- أداء عالٍ في التعامل مع البيانات الضخمة
- تكامل مع نظام Azure للتوسع السحابي

------------------------------------------------------------------------------

4.1.2 _security ------------------------------------------------------------------------------

يتضمن النظام منظومة أمنية متكاملة لحماية البيانات والمستخدمين:

- نظام JWT (JSON Web Tokens) للمصادقة الحقيقية (Stateless Authentication)
- استخدام BCrypt لتشفير كلمات المرور بمعامل تكلفة 12
- FluentValidation للتحقق من صحة المدخلات
- Rate Limiting لمنع هجمات العنف (Brute Force Attacks)
- نظام FluentValidation للتأكد من صحة جميع المدخلات

------------------------------------------------------------------------------

4.1.3 _architecture ------------------------------------------------------------------------------

ياتباع النظام هندسة نظيفة (Clean Architecture) صارمة تتكون من أربع طبقات رئيسية، حيث تعتمد كل طبقة على الطبقة الأدنى منها ولا تعرف شيئاً عن الطبقة الأعلى. هذا التصميم يضمن:

- فصل واضح بين المسؤوليات (Separation of Concerns)
- قابلية عالية للاختبار (Testability)
- سهولة الصيانة والتطوير (Maintainability)
- مرونة في استبدال المكونات (Replaceability)

================================================================================

4.2_arch_layers ===========================================================================
                           4.2 طبقات الهندسة النظيفة
--------------------------------------------------------------------------------

يتبنى نظام مُجاز نموذج الهندسة النظيفة (Clean Architecture) الذي صاغه روبرت سي مارتن (Robert C. Martin)، المعروف بـ Uncle Bob. يُعد هذا النموذج من أكثر النماذج فعالية في تطوير البرمجيات الحديثة.

------------------------------------------------------------------------------

4.2.1 _domain ===============================================================================

تُعد طبقة النطاق (Domain Layer)基礎 الأساسية التي يرتكز عليها النظام بالكامل. لا تحتوي هذه الطبقة على أي تبعيات خارجية، أي أنها مستقلة تماماً ولا تعرف شيئاً عن بقية النظام. تتضمن هذه الطبقة:

أ) الكيانات (Entities):
تمثل الكيانات الكائنات التجارية الأساسية للنظام. كل كيان يُعرّف بحد ذاته ومعرفه الفريد (GUID). من أهم الكيانات:

- User: يمثل المستخدم في النظام، سواء كان متقدماً بطلب أو موظفاً
- Application: يمثل طلب الحصول على رخصة قيادة
- License: يمثل الرخصة الصادرة
- LicenseCategory: يمثل فئة الرخصة (A, B, C, D, E, F)
- PaymentTransaction: يمثل معاملة الدفع
- Appointment: يمثل موعد الفحص أو الاختبار
- MedicalExamination: يمثل الفحص الطبي
- TheoryTest: يمثل الاختبار النظري
- PracticalTest: يمثل الاختبار العملي
- Document: يمثل المستند المُحمّل
- Notification: يمثل الإشعار الداخلي

ب) التعدادات (Enums):
تُستخدم التعدادلات لتعريف القيم الثابتة في النظام. تشمل:

- ApplicationStatus: حالة الطلب (Draft, Submitted, InReview, MedicalExam, Training, TheoryTest, PracticalTest, Approved, Payment, Issued, Active, Rejected, Cancelled, Expired)
- UserRole: دور المستخدم (Applicant, Receptionist, Doctor, Examiner, Manager, Security, Admin)
- ServiceType: نوع الخدمة (NewLicense, Renewal, Replacement, CategoryUpgrade)
- LicenseCategoryCode: код الفئة (A, B, C, D, E, F)
- FeeType: نوع الرسم (ApplicationFee, MedicalExamFee, TheoryTestFee, PracticalTestFee, IssuanceFee, RetakeFee)
- TestResult: نتيجة الاختبار (Pass, Fail, Absent)
- PaymentStatus: حالة الدفع (Pending, Paid, Failed, Refunded)

ج) Interfaces Interfaces)):
تعرّف هذه الطبقة عقود (Contracts) للخدمات التي تحتاجها من الطبقات الأخرى. تشمل:

- IRepository<T>: واجهة عامة للمستودعات
- IUnitOfWork: واجهة وحدة العمل
- IOtpRepository: واجهة مستودعات OTP

------------------------------------------------------------------------------

4.2.2 _shared ===============================================================================

تُشارك (Shared Layer) الطبقة المشتركة بين جميع الطبقات الأخرى. توفر هذه الطبقة:

أ) ApiResponse<T>: غلاف الاستجابة الموحد (Standard Response Wrapper)
هوكل موحد لجميع استجابات API يضمن تناسقاً كاملاً في تنسيق الردود:

```csharp
public class ApiResponse<T>
{
    public bool Success { get; set; }
    public string Message { get; set; }
    public T? Data { get; set; }
    public List<string>? Errors { get; set; }
    public int StatusCode { get; set; }
}
```

ب) PagedResult<T>: نتيجة الصفحات (Pagination)
تُستخدم لتغليف النتائج المُصفحّة:

```csharp
public class PagedResult<T>
{
    public List<T> Items { get; set; }
    public int TotalCount { get; set; }
    public int Page { get; set; }
    public int PageSize { get; set; }
    public int TotalPages { get; set; }
    public bool HasPreviousPage { get; set; }
    public bool HasNextPage { get; set; }
}
```

ج) Exceptions: الاستثناءات المخصصة
توفر فئات استثناء مخصصة للتعامل مع الأخطاء:

- MojazException: الاستثناء الأساسي
- NotFoundException: لم يتم العثور على المورد
- UnauthorizedException: غير مُصرَّح به
- ForbiddenException: ممنوع الوصول
- ConflictException: تعارض في البيانات
- ValidationException: خطأ في التحقق

------------------------------------------------------------------------------

4.2.3 _application ===========================================================================

تطبيق (Application Layer) الطبقة الثانية في الترتيب. تعتمد على طبقة النطاق والمُشاركة فقط، ولا تحتوي على أي مرجع مباشر لطبقة البنية التحتية. تتضمن:

أ) الخدمات (Services):
الخدمات هي جوهر العمل التجاري (Business Logic). تشمل الخدمات الرئيسية:

- ApplicationService: إدارة طلبات الرخص
- AuthService: المصادقة والتفويض
- PaymentService: إدارة المدفوعات
- LicenseService: إدارة الرخص
- AppointmentService: إدارة المواعيد
- NotificationService: إدارة الإشعارات
- DocumentService: إدارة المستندات
- ReportService: التقارير والإحصائيات

ب) الـ Validators:
تستخدم FluentValidation للتحقق من صحة المدخلات:

- CreateApplicationValidator: التحقق من طلب جديد
- LoginRequestValidator: التحقق من بيانات تسجيل الدخول
- UploadDocumentValidator: التحقق من المستندات

ج) التعيينات (Mappings):
تستخدم AutoMapper لتحويل الكيانات إلى كائنات النقل (DTOs):

- ApplicationProfile: تعيين بيانات الطلب
- UserProfile: تعيين بيانات المستخدم
- PaymentProfile: تعيين بيانات الدفع

------------------------------------------------------------------------------

4.2.4 _infrastructure ========================================================================

البنية التحتية (Infrastructure Layer) الطبقة الرابعة والأخيرة. تعتمد على جميع الطبقات الأخرى وتُنفّذ الواجهات المُعرّفة في طبقة التطبيق. تتضمن:

أ) MojazDbContext: سياق قاعدة البيانات
يعرّف جميع الجداول والعلاقات باستخدام Entity Framework Core:

```csharp
public class MojazDbContext : DbContext
{
    public DbSet<User> Users { get; set; }
    public DbSet<Application> Applications { get; set; }
    public DbSet<License> Licenses { get; set; }
    // ... باقي الجداول
}
```

ب) المستودعات (Repositories):
تنفيذ أنماط الوصول للبيانات:

- Repository<T>: مستودع عام
- ApplicationRepository: مستودع الطلبات
- LicenseRepository: مستودع الرخص

ج) الخدمات الخارجية (External Services):
- EmailService: إرسال البريد الإلكتروني (SendGrid)
- SmsService: إرسال الرسائل النصية (Twilio)
- PushNotificationService: الإشعارات الفورية (Firebase)
- FileStorageService: تخزين الملفات

------------------------------------------------------------------------------

4.2.5 _api ===========================================================================

طبقة API (API Layer) الطبقة الأخيرة التي تعمل كتركيب (Composition Root). تتضمن:

أ) Controllers: المتحكمات
تُعرّف نقاط النهاية (Endpoints) وتستقبل الطلبات من العملاء:

- ApplicationsController: نقاط نهاية الطلبات
- AuthController: نقاط نهاية المصادقة
- PaymentsController: نقاط نهاية المدفوعات

ب) Middleware: البرمجيات الوسيطة
- GlobalExceptionHandler: معالجة الاستثناءات عملياً
- SecurityHeadersMiddleware: إضافة头部 الأمنية

ج) Program.cs: تكوين التطبيق
تسجيل جميع الخدمات وتكوين DI Container

4.4_auth_flow ===========================================================================
                    4.4 تدفق المصادقة والتفويض
--------------------------------------------------------------------------------

يتضمن النظام منظومة مصادقة وتفويض متكاملة تستخدم JWT Tokens. فيما يلي التفاصيل:

------------------------------------------------------------------------------

4.4.1 _login_flow ---------------------------------------------------------------------

1. يرسل المستخدم طلب تسجيل الدخول مع (Email أو Phone) وكلمة المرور
2. يتحقق AuthService من صحة بيانات اعتماد المستخدم
3. يُبحث عن المستخدم في قاعدة البيانات
4. يُتحقق من صحة كلمة المرور المشفرة باستخدام BCrypt
5. يُتحقق من حالة الحساب (مُفعّل/مقفل)
6. يُنشأ Access Token (مدة ساعة واحدة)
7. يُنشأ Refresh Token (مدة 7 أيام)
8. يُخزّن Refresh Token في قاعدة البيانات
9. تُرجع الاستجابة مع الرموز

------------------------------------------------------------------------------

4.4.2 _jwt_structure ---------------------------------------------------------------------

يتكون JWT Token من three parts:

- Header: يحتوي على نوع الرمز وخوارزمية التوقيع
- Payload: يحتوي على المطالبات (Claims)
- Signature: التوقيع الرقمي

```json
{
  "sub": "user-id-guid",
  "role": "Applicant",
  "iat": 1715000000,
  "exp": 1715003600
}
```

المطالبات الرئيسية:
- sub: معرف المستخدم
- role: دور المستخدم
- iat: وقت الإصدار
- exp: وقت الانتهاء

------------------------------------------------------------------------------

4.4.3 _authorization -----------------------------------------------------

يستخدم النظام Role-Based Authorization (RBAC). الأدوار المحددة:

- Applicant: مُقدّم الطلب - يقرأ ويعدل طلباته فقط
- Receptionist: موظف الاستقبال - مراجعة الوثائق
- Doctor: طبيب الفحص الطبي - تسجيل النتائج الطبية
- Examiner: مُمتحن النظري والعملي - تسجيل نتائج الاختبارات
- Manager: المدير - الاعتماد النهائي
- Security: الأمني - التحقق الأمني
- Admin: المدير العام - إدارة النظام

------------------------------------------------------------------------------

4.4.4 _security_gates ---------------------------------------------------------------------

يتضمن النظام أربع بوابات للتحقق (Gates) في مراحل الطلب:

- البوابة الأولى (Gate 1): التحقق من أهلية مقدم الطلب (السن، عدم وجود طلب نشط، الحظر الأمني)
- البوابة الثانية (Gate 2): مرا��عة الوثائق والأصالة
- البوابة الثالثة (Gate 3): الفحص الطبي والنظري والعملي
- البوابة الرابعة (Gate 4): التحقق الأمني النهائي

4.5_database_schema ======================================================================
                         4.5 نظرة عامة على مخطط قاعدة البيانات

- Role: الدور
- IsActive: الحالة
- IsSecurityBlocked: حالة الحظر الأمني
- CreatedAt: وقت الإنشاء
- UpdatedAt: وقت التحديث

4.5.2 _applications_table ------------------------------------------------------------------

الجدول: Applications
الوصف: تخزين طلبات الرخص

5.3.2 _global_handler -----------------------------------------------------------

معالج الاستثناءات العام (Global Exception Handler):

```csharp
public class GlobalExceptionHandler : IExceptionHandler
{
    private readonly ILogger<GlobalExceptionHandler> _logger;
    private readonly IAuditService _auditService;

    public async Task HandleExceptionAsync(ExceptionContext context)
    {
        var exception = context.Exception;

        _logger.LogError(exception, "Unhandled exception occurred");

        switch (exception)
        {
            case NotFoundException ex:
                context.Result = new NotFoundObjectResult(
                    ApiResponse<object>.Fail(ex.Message, ex.StatusCode));
                break;
            case UnauthorizedException ex:
                context.Result = new UnauthorizedObjectResult(
                    ApiResponse<object>.Fail(ex.Message, ex.StatusCode));
                break;
            case ValidationException ex:
                context.Result = new BadRequestObjectResult(
                    ApiResponse<object>.Fail(ex.Message, ex.StatusCode, ex.Errors));
                break;
            default:
                context.Result = new ObjectResult(
                    ApiResponse<object>.Fail(
                        "حدث خطأ داخلي. يرجى المحاولة لاحقاً.", 500))
                {
                    StatusCode = 500
                };
                break;
        }

        context exceptionHandled = true;
    }
}
```

```csharp
public async Task<PagedResult<T>> GetPagedAsync<T>(
    IQueryable<T> query,
    int page,
    int pageSize)
{
    var total = await query.CountAsync();
    var items = await query
        .OrderByDescending(x => x.CreatedAt)
        .Skip((page - 1) * pageSize)
        .Take(pageSize)
        .ToListAsync();

    return new PagedResult<T>
    {
        Items = items,
        TotalCount = total,
        Page = page,
        PageSize = pageSize,
        TotalPages = (int)Math.Ceiling(total / (double)pageSize)
    };
}
```

5.6.2 _jwt_generation -----------------------------------------------------------

توليد JWT Tokens:

```csharp
public class JwtService : IJwtService
{
    public string GenerateToken(User user)
    {
        var claims = new List<Claim>
        {
            new Claim(ClaimTypes.NameIdentifier, user.Id.ToString()),
            new Claim(ClaimTypes.Email, user.Email ?? ""),
            new Claim(ClaimTypes.Role, user.Role.ToString()),
            new Claim(JwtRegisteredClaimNames.Jti, Guid.NewGuid().ToString())
        };

        var key = new SymmetricSecurityKey(
            Encoding.UTF8.GetBytes(_settings.SecretKey));
        var credentials = new SigningCredentials(
            key, SecurityAlgorithms.HmacSha256);

        var token = new JwtSecurityToken(
            issuer: _settings.Issuer,
            audience: _settings.Audience,
            claims: claims,
            expires: DateTime.UtcNow.AddMinutes(60),
            signingCredentials: credentials);

        return new JwtSecurityTokenHandler().WriteToken(token);
    }
}
```

5.6.3 _file_validation -----------------------------------------------------------

التحقق من الملفات المُحمّلة:

```csharp
public class FileValidationService : IFileValidationService
{
    private static readonly HashSet<string> AllowedExtensions =
        new HashSet<string>(StringComparer.OrdinalIgnoreCase)
        {
            ".jpg", ".jpeg", ".png", ".pdf"
        };

    private const long MaxFileSize = 5 * 1024 * 1024; // 5MB

    public async Task<bool> ValidateAsync(IFormFile file)
    {
        if (file.Length > MaxFileSize)
            return false;

        var extension = Path.GetExtension(file.FileName);
        if (!AllowedExtensions.Contains(extension))
            return false;

        using var stream = file.OpenReadStream();
        var header = new byte[4];
        var bytesRead = await stream.ReadAsync(header, 0, 4);

        // التحقق من توقيع الملف
        var signature = BitConverter.ToString(header);
        return signature.StartsWith("FF-D8-FF") || // JPEG
               signature.StartsWith("89-50-4E") || // PNG
               signature.StartsWith("25-50-44-46"); // PDF
    }
}
```
